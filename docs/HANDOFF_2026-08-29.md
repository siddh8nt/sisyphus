## 4. MOVE THE 3 PHONES TO siddh's HUB

Per phone (all 3 identical, `iqoo-1/2/3`):

### CPU endpoint + telemetry (over Wi-Fi, no USB)
1. Phone joins siddh's hotspot.
2. In Termux, re-run the one-liner against siddh's hub IP (idempotent — skips the
   2 GB model pull, re-registers, relaunches telemetry with the fixed script):
   ```
   curl -s http://192.168.137.1:4100/setup.sh | sh -s -- --name iqoo-1
   ```
3. Keep Termux in the FOREGROUND, or set Android → Apps → Termux → Battery →
   **Unrestricted**. Android kills backgrounded Termux → telemetry stops → phone
   flips offline → no task dispatch. This is the #1 live-demo fragility.

### NPU endpoint (needs USB once per phone)
Enable USB debugging on the phone (Settings → About → tap Build number 7× →
Developer options → USB debugging), plug in, accept the RSA prompt. Then, on the
hub — **target by serial** if the OnePlus (or any other device) is also attached:

- If the on-device bundle is intact (normal case) — just (re)start + register,
  no 2 GB push:
  ```
  phone\npu\start-npu.ps1 -Name iqoo-1 -Serial 10BFBM0AU7001GP
  ```
- If /data/local/tmp was wiped, or unsure — full re-push (needs `phone/npu/bundle/`
  on the laptop, §3c):
  ```
  phone\npu\deploy-npu.ps1 -Name iqoo-1 -Serial 10BFBM0AU7001GP
  ```
Both auto-detect the phone's new Wi-Fi IP, poll `:8080`, and register the NPU
endpoint (groups with the CPU endpoint by `--name`). The adb-hang bug is fixed,
so this completes hands-off.

You can unplug a phone as soon as its NPU endpoint registers — `llama-server`
keeps serving over Wi-Fi; USB was only for the adb push/start.

### Verify
```
curl -s http://127.0.0.1:4100/api/phones
```
Want: 3 phones `status=online`, each with `cpu` + `npu` endpoints `healthy=true`,
`activeRuntime=npu`.
